# Codemod engine (V3-16aR)

AST-based, import-only migration of Tauri module imports to the
platform registry (`@/lib/platform`), for waves G1-G5 (V1-05
section 4, AD-41). The engine edits import declarations and nothing
else. It never rewrites call sites, string literals, comments, or
other statements, and every run ends with a self-check proving the
non-import text is byte-identical before and after the transform.

## Scope boundary (read before running)

- Static imports: transformed when every binding in the declaration
  has a known mapping for the run wave (see `mappings.mjs`). The
  binding is removed and an import of `platform` from the registry
  barrel is ensured, or the binding is re-imported from the barrel
  under the same name (alias preserved). Call sites are NOT
  rewritten; the JSON report lists every reference with a suggested
  replacement expression, and the wave worker (3C) applies the
  call-site rewrites, then typechecks.
- Dynamic `import()`: reported, never edited, unless the caller
  opts in with `--rewrite-dynamic-imports`, and even then only the
  specifier literal of a fully barrel-mappable destructure is
  rewritten. `Promise.all` batches are never partially rewritten:
  the whole batch is reported as one unit for the wave worker.
- `window.__TAURI_INTERNALS__` and its string form are reported,
  never edited. Namespace imports, side-effect imports, and
  re-exports are reported and skipped.
- A declaration the engine cannot handle safely is skipped with a
  reason (see below), never guessed. Unknown import names fail the
  declaration closed. Blind global `sed` is forbidden.

## Tool choice

`ts-morph` (TypeScript compiler AST). It parses `.ts`/`.tsx`,
resolves references, and distinguishes type positions from value
positions, which the engine needs for type-only barrel exports.
Edits are text spans computed from AST nodes, so formatting and
comments are preserved exactly; nothing is reprinted. `jscodeshift`
was rejected: it needs separate TypeScript parser wiring, reprints
through recast (reformatting risk), and has weaker type-position
analysis. Full justification: `fase1/laporan-v3-16a-codemod-engine.md`.

## Dependency

`ts-morph ^28.0.0` is a root `devDependencies` entry (tooling only;
never in the production bundle). The lockfile is regenerated by the
integrator (AD-41, N-8); workers do not hand-edit it. If `ts-morph`
is missing, the engine exits with a clear install message.

## Usage (from the repo root)

Dry-run is the default: diffs print, nothing is written.

```sh
node scripts/codemod/run.mjs --wave G1 --files <list-file>
node scripts/codemod/run.mjs --specifier @tauri-apps/plugin-store --files <list-file>
node scripts/codemod/run.mjs --wave G1 --files <list-file> --report out.json
node scripts/codemod/run.mjs --wave G1 --files <list-file> --write
```

One `--wave` (G1-G5) or one `--specifier` is required, never both.
Files come from `--files` (one relative path per line; `#` comments
and blank lines ignored) and/or positional paths, relative to
`--root` (default: current directory).

| Flag | Meaning |
|---|---|
| `--wave G1..G5` | Transform only bindings owned by that wave; other bindings of a shared specifier stay in a residual declaration. |
| `--specifier <spec>` | Transform every mapped binding of one specifier, regardless of wave. Wave discipline is the caller's job. |
| `--files <list>` | File list, one relative path per line. |
| `--root <dir>` | Repo root for relative paths (default: cwd). |
| `--write` | Apply transforms. Without it, dry-run only. |
| `--report <path>` | Write the JSON report (schema version 1). |
| `--diff` / `--no-diff` | Print unified diffs (default: print). |
| `--strict` | Exit 1 when any file is skipped (default: 0). |
| `--rewrite-dynamic-imports` | Opt-in dynamic rewrite, all-barrel-value destructures only. |
| `--help` | Print usage and exit 0. |

Exit codes: 0 means completed (skips allowed unless `--strict`);
1 means usage error, any file error, or (with `--strict`) any
skipped file.

Full specifier strings carry the `@tauri-apps/` prefix (except
`tauri-plugin-clipboard-api`). `api/core` spans three waves per
binding: `invoke`/`Channel`/`transformCallback` at G2,
`convertFileSrc` at G3, `isTauri` at G4. The gate wave map in
`scripts/gates/waves.json` (V3-16b) lists `api/core` once; the
engine list is per binding, not per specifier. See the alignment
note in the fase1 report.

## The 8 import patterns (V1-05 section 4.3)

| # | Pattern | Handling | Fixture |
|---|---|---|---|
| 1 | Static one-line import, either quote style, optional semicolon | Transform | `engine-fixtures/engine-f01-store.ts` |
| 2 | Static multi-line import block | Transform (AST, not lines) | `engine-fixtures/engine-f02-multiline.ts` |
| 3 | Type imports (`import type`, inline `type`, type-only barrel exports) | Transform when every reference is in a type position, else skip | `engine-fixtures/engine-f03-types.ts` |
| 4 | Aliases (`open as openDialog`, ...) | Transform; local name preserved | `engine-fixtures/engine-f04-alias.ts` |
| 5 | Dynamic import (`await import`, `.then`, `Promise.all` batch) | Report only by default; batch reported as one unit; opt-in rewrite for all-barrel-value destructures | `engine-fixtures/engine-f05-dynamic.ts`, `engine-f18-dynamic-barrel.ts` |
| 6 | Dynamic module access (`module.Store.load`) | Report only (namespace access) | `engine-fixtures/engine-f06-module-access.ts` |
| 7 | Combined imports (two specifiers, duplicate declarations) | Transform per specifier per wave; residual kept | `engine-fixtures/engine-f07-combined.ts`, `engine-f11-core-partial.ts` |
| 8 | Use without a direct import (`__TAURI_INTERNALS__`, `getCurrentWindow`) | Marker: report only. `getCurrentWindow`: transform the import, report references with replacement | `engine-fixtures/engine-f08-internals.ts`, `engine-f19-window.ts` |

Edge fixtures: `engine-f09` (name collision), `engine-f10`
(default import + no-equivalent type), `engine-f12` (existing
barrel import, no duplicate), `engine-f13` (barrel type used as a
value, skip), `engine-f14` (platform + barrel value in one
declaration), `engine-f15` (no-equivalent name fails the whole
declaration), `engine-f16` (namespace, side-effect, re-export),
`engine-f17` (merge into existing barrel imports).

## Report

`--report` writes JSON, schema version 1: totals plus one object
per file (`status`, `declarationsTransformed`,
`declarationsSkipped` with `reason`, `declarationsDeferred`,
`bindings` with `references` and `replacement`,
`dynamicImports`, `notes`). Statuses: `transformed`,
`unchanged`, `skipped`, `error`.

Skip reasons for declarations: `namespace-import`,
`side-effect-import`, `unknown-import-name`,
`unknown-default-import`, `no-barrel-equivalent`,
`barrel-type-used-as-value`, `barrel-name-taken`,
`name-collision-platform`, `platform-name-taken`,
`default-import-barrel`. Dynamic reasons: `promise-all-batch`,
`dynamic-namespace-access`, `dynamic-then-access`,
`dynamic-import-unclassified`, `dynamic-unknown-name`,
`dynamic-import-needs-manual`, `dynamic-specifier-non-literal`,
`rewritten`. Notes: `re-export-not-handled`,
`tauri-internals-marker`, `unsupported-extension`.

## Wave worker workflow (3C)

1. Dry-run the wave over a file list; review every printed diff.
2. Run with `--write` and `--report`; keep the report.
3. Rewrite call sites using the report `bindings`/`replacement`
   entries (the engine does not do this step).
4. Typecheck in batches of at most 20 files; fix before continuing.
5. Run the 4-layer gate (`scripts/gates/`, V3-16b) before merge.

Verify the engine itself over copies, never over the committed
fixtures in place:

```sh
mkdir -p ~/workspace/codemod-check
cp scripts/codemod/engine-fixtures/engine-*.ts ~/workspace/codemod-check/
node scripts/codemod/run.mjs --wave G1 --root ~/workspace/codemod-check --report report.json engine-f01-store.ts
```

## Files

- `run.mjs`: CLI (stable interface for gates and fixtures).
- `engine.mjs`: AST transform + import-only self-check.
- `mappings.mjs`: per-name mapping tables and wave lists.
- `report.mjs`: unified diff + report summary helpers.
- `engine-fixtures/`: engine-owned verification inputs.
- `fixtures/`: owned by V3-16c (before/after pairs + guide);
  not owned by this task, do not edit here.
